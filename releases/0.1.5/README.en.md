# huihui 无限画布 MCP 0.1.5

[简体中文安装说明](INSTALL.zh-CN.md)

Connect a local Codex client to your signed-in Infinite Canvas browser tab. The package provides a local Bridge and a stdio MCP server; it stores no cloud login token. Requires Node.js 22+ and Codex on the same computer as the browser.

Canvas: [https://lc.tatakeji.cn/](https://lc.tatakeji.cn/). Open your own canvas after signing in; the matching Web and Canvas Service must be deployed for the new tools.

## Quickstart

First sign in to Canvas, open the canvas you want to edit, and replace the URL below with that canvas's actual URL. Then send this to your **local** agent:

> Read the supplied README and the distribution README at https://github.com/AlexCh121/canvas-mcp-dist first. My signed-in canvas is `<PASTE_YOUR_CANVAS_URL>`. Install the supplied `qorigin-canvas-mcp-0.1.5.tgz` after verifying `SHA256SUMS-0.1.5`. Register `huihui-canvas` with Codex, keep the local Bridge running, and guide me through pairing in Canvas Assistant → Codex. List and explicitly select my browser connection. Ask which local material folder I want to authorize before enabling uploads. If you cannot run on this computer or keep the Bridge running, explain that limitation.

## Install and pair

Download the archive and checksum from the [v0.1.5 release](https://github.com/AlexCh121/canvas-mcp-dist/releases/tag/v0.1.5), then run:

```bash
shasum -a 256 -c SHA256SUMS-0.1.5
npm install -g ./qorigin-canvas-mcp-0.1.5.tgz
codex mcp add huihui-canvas -- qorigin-canvas-mcp mcp
qorigin-canvas-mcp serve
```

Keep the terminal open. Enter its one-use pairing code in **Canvas Assistant → Codex**. Call `canvas_list_connections`, then `canvas_select_connection` with the connection ID shown in Canvas. To issue another pairing code, run `qorigin-canvas-mcp pair` while the Bridge is running. Before upgrading, use `codex mcp list` to check existing registrations and remove obsolete `qorigin-canvas`, `qorigin-canvas-dev` or `qorigin_canvas_dev` entries to avoid duplicate tools. If `huihui-canvas` already exists, replace its registration. Stop the old Bridge before starting this version; keep its private state directory for recovery.

To enable local uploads, restart the Bridge with an explicitly authorized directory (repeat for additional directories):

```bash
qorigin-canvas-mcp serve --upload-root /absolute/path/to/materials
```

Only regular files inside those directories can be read. URL inputs and paths escaping through symlinks are refused. Call `canvas_get_upload_options` before uploading. Each batch accepts at most 20 files; business and deployment limits can lower this. The initial transport budget is 64 MiB per file, 512 MiB per batch and at most four transfers; the browser holds at most 128 MiB of pending file blobs. MiB = 1,048,576 bytes. Snapshots remain readable for 24 hours; the running Bridge cleans expired files periodically and on startup. Common binary image/video formats and MP3/WAV are detected from bytes; unsupported or unrecognizable files receive per-item errors. Upload acceptance does not guarantee browser preview or model compatibility.

## Create and iterate

- Page through `canvas_get_state`; read text with `canvas_get_node_text` until `nextOffset` is null before replacing long scripts.
- Use exact media versions from `canvas_list_media_versions` for previews, reviews and references. Review tools report supplier compliance, separately from creative quality.
- Before a write, call `canvas_prepare_operation` and keep its ID. Free actions execute automatically in Canvas after pairing; your MCP client's own tool approvals remain under that client's control.
- Configure a generation node, obtain a quote and pass its fingerprint, prompt, references and amount unchanged to the generation tool. Paid generation requires confirmation in Canvas. Independent nodes can generate concurrently, preserving old results.
- `canvas_upload_materials` returns an asynchronous receipt. Query its original operation ID until each node and version is confirmed; never resend an uncertain batch using a new ID.
- `canvas_create_generation_batch` saves up to 20 independent image/video targets. Canvas quotes and confirms each paid item and advances the queue while online. Pause/resume controls only unsubmitted work. A changed quote or input pauses the plan for inspection; submitted or unknown items are never regenerated by resuming.
- `committed` means submission is confirmed. Check generation status and persisted result versions separately. Missing evidence remains `outcome_unknown` with no permission to repeat the charge.

After a refresh, reopen Canvas Assistant → Codex to restore the connection. While that panel is unmounted, background reconnection is unavailable. Refreshes and Bridge restarts can recover the same pairing and operation IDs while authorization remains valid. Explicit disconnect revokes it. Recovery needs the current signed-in user's permissions; expired authorization requires pairing again. Authorization lasts 24 hours, can renew while online, and requires fresh pairing after seven days.

## Configuration and scope

`QORIGIN_CANVAS_ORIGINS` can specify the exact Origin of another authorized deployment; an empty value is refused. `QORIGIN_CANVAS_MCP_PORT` changes the loopback port and `QORIGIN_CANVAS_MCP_HOME` the private state directory. Transport budgets can be lowered with `QORIGIN_CANVAS_UPLOAD_MAX_FILE_BYTES`, `QORIGIN_CANVAS_UPLOAD_MAX_BATCH_BYTES`, and `QORIGIN_CANVAS_UPLOAD_SNAPSHOT_BYTES`.

This version requires the matching Canvas Web and Canvas Service upload/batch APIs. DEV checks covered overlapping image/video generation, a six-image queue with refresh recovery, regeneration/version selection, confirmation-time price changes, lease takeover, pairing revocation, upload idempotency and a 64 MiB file boundary. This is a prerelease; production deployment acceptance is tracked separately. HEIC uploads can be stored but currently fail preview decoding and width/height extraction; use PNG or JPEG when a visual client or model must read the image. HEIF and model compatibility require separate validation. Six-video uninterrupted recovery, actual membership revocation and aggregate upload capacity remain unverified. This package is distributed as a tarball, not on npm. Remote execution, unattended queues, video frame extraction, dubbing, editing and export are outside this version. Temporary media URLs remain usable until they expire. Retained unimported objects require business-side inspection; the Bridge never deletes an object after an uncertain upload.
