# huihui 无限画布 MCP 0.1.9

[简体中文安装说明](INSTALL.zh-CN.md)

Use your authorized Canvas URL. Sign in and open your own canvas before pairing.

This is the 0.1.9 release. The default installation is specified by the distribution repository latest.json. Cross-canvas pairing requires matching Canvas Web; upload prompts and visible upload names require matching Canvas Service. Package publication does not deploy services. Real customer workflows and the intermittent disconnect trigger remain under validation.

Connect a local Codex client to your signed-in Infinite Canvas browser tab. The package provides a local Bridge and a stdio MCP server; it stores no cloud login token. Requires Node.js 22+ and Codex on the same computer as the browser.

## Quickstart

First sign in to Canvas, open the canvas you want to edit, and replace the URL below with that canvas's actual URL. Then send this to your **local** agent:

> Read the supplied README and the distribution README at https://github.com/AlexCh121/canvas-mcp-dist first. My signed-in canvas is `<PASTE_YOUR_CANVAS_URL>`. Install the supplied `qorigin-canvas-mcp-0.1.9.tgz` after verifying `SHA256SUMS-0.1.9`. Register `huihui-canvas` with Codex, derive its exact Origin as `QORIGIN_CANVAS_ORIGINS` and keep the local Bridge running, and guide me through pairing in Canvas Assistant → Codex. List and explicitly select my browser connection. Ask which local material folder I want to authorize before enabling uploads. If you cannot run on this computer or keep the Bridge running, explain that limitation.

## Install and pair

Download the versioned archive and checksum from [GitHub Releases](https://github.com/AlexCh121/canvas-mcp-dist/releases). Run:

```bash
CANVAS_URL='PASTE_YOUR_CANVAS_URL_HERE'
CANVAS_ORIGIN="$(node -p 'new URL(process.argv[1]).origin' "$CANVAS_URL")"
shasum -a 256 -c SHA256SUMS-0.1.9
npm install -g ./qorigin-canvas-mcp-0.1.9.tgz
codex mcp add huihui-canvas -- qorigin-canvas-mcp mcp
QORIGIN_CANVAS_ORIGINS="$CANVAS_ORIGIN" qorigin-canvas-mcp serve
```

Keep the terminal open. Enter its one-use pairing code in **Canvas Assistant → Codex**. Call `canvas_list_connections`, then `canvas_select_connection` with the connection ID shown in Canvas. To issue another pairing code, run `qorigin-canvas-mcp pair` while the Bridge is running. Remove an obsolete `qorigin-canvas-dev` registration when upgrading.

To enable local uploads, restart the Bridge with an explicitly authorized directory (repeat for additional directories):

```bash
QORIGIN_CANVAS_ORIGINS="$CANVAS_ORIGIN" qorigin-canvas-mcp serve --upload-root /absolute/path/to/materials
```

Only regular files inside those directories can be read. URL inputs and paths escaping through symlinks are refused. Call `canvas_get_upload_options` before uploading. Each batch accepts at most 20 files; business and deployment limits can lower this. The initial transport budget is 64 MiB per file, 512 MiB per batch and at most four transfers; the browser holds at most 128 MiB of pending file blobs. MiB = 1,048,576 bytes. Snapshots remain readable for 24 hours; the running Bridge cleans expired files periodically and on startup. Common binary image/video formats and MP3/WAV are detected from bytes; unsupported or unrecognizable files receive per-item errors. Upload acceptance does not guarantee browser preview or model compatibility.

## Create and iterate

- Page through `canvas_get_state`; read text with `canvas_get_node_text` until `nextOffset` is null before replacing long scripts.
- Use exact media versions from `canvas_list_media_versions` for previews, reviews and references. Review tools report supplier compliance, separately from creative quality.
- Before a write, call `canvas_prepare_operation` and keep its ID. Free actions execute automatically in Canvas after pairing; your MCP client's own tool approvals remain under that client's control.
- Configure a generation node, obtain a quote and pass its fingerprint, prompt, references and amount unchanged to the generation tool. Paid generation requires confirmation in Canvas. Independent nodes can generate concurrently, preserving old results.
- `canvas_upload_materials` returns an asynchronous receipt. Query its original operation ID until each node and version is confirmed; never resend an uncertain batch using a new ID.
- `canvas_create_generation_batch` saves up to 20 independent image/video targets. Canvas quotes and confirms each paid item and advances the queue while online. Pause/resume controls only unsubmitted work. A changed quote or input pauses the plan for inspection; submitted or unknown items are never regenerated by resuming.
- `committed` means submission is confirmed. Check generation status and persisted result versions separately. Missing evidence remains `outcome_unknown` with no permission to repeat the charge.

Refreshes and Bridge restarts can recover the same pairing and operation IDs while authorization remains valid. Explicit disconnect revokes it. Recovery needs the current signed-in user's permissions; expired authorization requires pairing again. Authorization lasts 24 hours, can renew while online, and requires fresh pairing after seven days.

## Configuration and scope

`QORIGIN_CANVAS_ORIGINS` can specify the exact Origin of another authorized deployment; an empty value is refused. `QORIGIN_CANVAS_MCP_PORT` changes the loopback port and `QORIGIN_CANVAS_MCP_HOME` the private state directory. Transport budgets can be lowered with `QORIGIN_CANVAS_UPLOAD_MAX_FILE_BYTES`, `QORIGIN_CANVAS_UPLOAD_MAX_BATCH_BYTES`, and `QORIGIN_CANVAS_UPLOAD_SNAPSHOT_BYTES`.

This version requires the matching Canvas Web and Canvas Service upload/batch/name APIs. The connection changes need the matching Web hook; local regression checks do not replace DEV or production acceptance. This package is distributed as a tarball, not on npm. Remote execution, unattended queues, video frame extraction, dubbing, editing and export are outside this version. Temporary media URLs remain usable until they expire. Retained unimported objects require business-side inspection; the Bridge never deletes an object after an uncertain upload.

## Reliability and batch tools

Version 0.1.9 extends 0.1.8 without removing tools. Its 42 actual tools are captured in `schema/customer-tools.v0.1.9.json`; earlier schemas are retained for reference. Web and Canvas Service must declare `save_only_graph_v2` before graph tools run; missing support returns `FEATURE_UNAVAILABLE`.

Connections live at page level, renew with bounded retries, and provide `canvas_get_connection_diagnostics`. Accepted uploads use a separate scope from SSE; unrelated revisions do not restart byte transfer. Explicit disconnect, revoked permissions, navigation, authorization expiry, or a closed browser still stop subsequent work.

For bulk preparation, read `canvas_get_mcp_capabilities`, then validate and apply a `save_only` graph plan using a prepared operation ID. Query `canvas_get_graph_operation` and paged item receipts. Read `canvas_get_graph_snapshot` with `prompt/references/parameters` projections; bind subsequent pages and text chunks to `expectedRevision`. `rawPrompt` and `resolvedPrompt` have independent lengths, UTF-8 hashes and next offsets counted in Unicode code points. Oversized expansion or response pages fail explicitly; request a smaller page.

Plans save up to 200 items and 2,000 edge changes within 768 KiB, subject to lower runtime settings; each advance commits at most 10 items. Updates require the current recipe fingerprint. Media references bind exact versions, and unknown `@[node:ID]` tokens fail. Audio references can be saved but generation explicitly refuses them. Saved recipes are separate from model compatibility and generation readiness; generation still needs a fresh quote and confirmation. See the release validation record for tested scenarios. Customer intermittent disconnects, real system sleep/background behavior, external proxy failures and unsupported audio generation remain explicit limitations. An idle edit lease is reacquired only when available; conflicting drafts or another editor are never overwritten.

An accepted save-only graph continues after transient service errors by reconciling server state and retrying the same advance request. Queries retain the original operation ID and expose any local blocker; a timeout never authorizes a new plan. Draft conflicts, control changes and revoked permissions stop automatic continuation.

Confirmed uploads retain their committed state while missing media metadata is checked again under current permissions. Query the original operation ID to refresh its receipt; metadata repair uses the original item and media version and never retransmits the uploaded bytes. A failed optional probe leaves metadata pending and does not permit another upload.


## Node display names

Version 0.1.7 adds `canvas_rename_node` for the visible names of text, image, video, audio and config nodes. Read `displayName` from `canvas_get_node` or the paged state; `title` remains internal. Prepare an operation ID, then call the rename tool with `nodeId` and `displayName`. Names are trimmed, must contain 1–200 characters, and may duplicate other names. Renaming spends no credits and preserves text, media versions and generation references; normal edit permission, lease and node-busy checks apply.

Both Web and Canvas Service must support `node_display_name_v1`; an incompatible deployment is rejected before dispatching the write. Query the original operation ID after an uncertain result. Renaming follows the same atomic receipt and replay rules as other ordinary writes. Use `canvas_update_node_text` only for plain-text content or its internal title, never to rename an image.

The tool is included in 0.1.7 and documented in `schema/customer-tools.v0.1.7.json`. Deploy matching Web and Canvas Service support before using it; publishing this package does not deploy either service. DEV acceptance covered text and image renaming, later manual edits, lost-receipt recovery and refresh persistence. Long-duration disconnect, multi-user revocation and paid-generation acceptance remain separate.

## Connection diagnosis and recovery

`canvas_list_connections` separates `transportStatus`, `browserStatus`, and `authorizationStatus`. `connected` requires a browser ACK or tool result within 45 seconds. An open stream waiting for its first response is `connecting`; a silent stream is `unresponsive`; a closed stream with a valid grant is `reconnecting`. None proves authorization expiry. `lastSeenAt` is the last heartbeat **sent**, not acknowledged.

A new MCP session can select a valid offline binding for diagnostics, or call `canvas_get_connection_diagnostics` with its original `connectionId` directly. Business tools still require the browser online and normal Canvas authorization. Missing local bindings return `unavailable` with `authorizationStatus: unverified`; verify the original Bridge process, port and private directory. Do not re-pair or repeat uncertain writes solely because of a timeout.

The matching Web preserves the original binding after an ambiguous resume rejection, retries that same resume attempt at most three times, then pauses with guidance to check the original Bridge and refresh. Only a verified expiry response requests re-pairing. Explicit disconnect and confirmed business permission revocation keep their existing behavior.

Bridge diagnostics keep up to 100 allowlisted lifecycle events per binding, with 30-day file retention; ACK telemetry writes are limited to once per minute. Browser evidence keeps up to 100 events per canvas/account scope in localforage, with heartbeat writes limited to once per 30 seconds. It records visibility, freeze/resume, network, renewal and recovery stages, without credentials, prompts or media URLs. Optional diagnostic storage failure does not revoke authorization. Old timestamps are historical evidence, not proof of a live browser after restart.

This patch fixes confirmed state classification, offline diagnosis and premature binding deletion. It does not establish or eliminate the original customer disconnect trigger; real background, sleep and long-running acceptance are still required.


Optional pairing reuse connects additional canvases only within the same Origin, account and team for up to seven days. Each canvas retains an independent connection ID and explicit MCP selection. Disconnect revokes the reusable grant and its children; permission and lease checks still apply.

Upload title becomes the visible node name. Optional prompt is stored verbatim on that media node without creating a text node or running generation. Check upload_prompt_v1 before using it. Configure models using canvas_get_generation_options and canvas_configure_generation before quoting; paid quote approval remains in Canvas.
